C++23语言特性记录

发表于2026-06-05|更新于2026-06-05|C++
|总字数:1.1k|阅读时长:3分钟|浏览量:

前言

记录来自 这里 的 C++23 语言特性。只是拙劣地翻译一下，可以点击前面的链接查看原文。

正文

C++23语言特性

consteval if

编写在常量求值期间实例化的代码。

C++ 
consteval int f(int i) { return i; }constexpr int g(int i) {  if consteval {      return f(i);  } else {      return 42;  }}

译者的理解：一般这种需要区分编译期还是运行时的需求，是在 constexpr 函数里的。这种函数编译期运行时都能用，有时候可能运行时需要一些优化什么的，而编译期不允许这么做，就得区分开。在 C++20 的时候，有个函数 std::is_constant_evaluated，用以区分。但是这个只是个普通函数，用 if 判断，结果两个分支都会需要编译期实例化，导致不能处理一些运行时优化。现在有了 if consteval，这个问题就迎刃而解了。编译期只会实例化编译期的分支，就可以在运行时分支塞一些奇怪的优化了。

Deducing this

C++23 引入的显式对象成员函数，现在可以通过在成员函数的首个参数前添加 this 关键字，来推导对象的类型和值类别：

C++ 
// 使用 Deducing this 的新做法:struct T {  decltype(auto) operator[](this auto& self, std::size_t idx) {    return self.mVector[idx];  }};// 老做法:struct T {  value_t& operator[](std::size_t idx) {    return mVector[idx];  }  const value_t& operator[](std::size_t idx) const {    return mVector[idx];  }};

译者的理解：这个 Deducing this 还有个用途就是用在奇异递归模板（CRTP）上。之前写 CRTP 的话，得把基类搞成模板类，然后再 static_cast<Derived*>(this) 再调用函数，很繁琐。而且为了减少二进制体积，还得把一些普通函数拆出去，再搞一个基类。现在不需要这么麻烦了，现在的例子：

C++ 
// 以前的做法：template <typename Derived>struct Base {    void do_something() {        // 得强转类型，如果继承树大一点再转错了什么的        static_cast<Derived*>(this)->impl();    }};// 继承的时候得把自己的类型填到基类模板里struct Derived : Base<Derived> {    void impl() { /* ... */ }};// 现在的做法struct Base {    template <typename Self>    void do_something(this Self&& self) {        // 甚至还能做完美转发，之前这种函数得写一堆，就懒得写了        std::forward<Self>(self).impl();    }};// 基类不需要是模板类了！哪个函数使用子类就把哪个函数搞成模板函数就行struct Derived : Base {    void impl() { /* ... */ }};

多维下标运算符重载

在 operator [] 运算符中可以指定 0 或更多参数：

C++ 
template <typename T, std::size_t Z, std::size_t Y, std::size_t X>struct Array3d {  std::array<T, X * Y * Z> m{};  T& operator[](std::size_t z, std::size_t y, std::size_t x) {      return m[z * Y * X + y * X + x];  }};Array3d<int, 4, 3, 2> v;v[3, 2, 1] = 42;

译者的理解：C++ 这门语言确实比较逆天，之前重载中括号只让有一个参数。结果这种多维坐标的我都拿小括号，非常丑。终于在 C++23 能够用上多个参数的重载中括号了🤡

提升范围 for 循环的安全性

修复了 C++ 中一种非常重要的控制结构的一些臭名昭著的问题。
下面是一些代码片段的实例，这些代码在 C++23 之前无法正常运行，现在已经修复：

  • for (auto e : getTmp().getRef())
  • for (auto e : getVector()[0])
  • for (auto valueElem : getMap()["key"])
  • for (auto e : get<0>(getTuple()))
  • for (auto e : getOptionalCollection().value())
  • for (char c : get<std::string>(getVariant()))

C++23库特性

堆栈追踪库

堆栈追踪是对调用序列的近似表示，是由多个堆栈追踪条目组成的。一个堆栈追踪条目 （表示成 std::stacktrace_entry）包含源文件、行号以及描述字段等信息。

一个 Linux 系统上的输出示例：

C++ 
#include <print>#include <stacktrace>int main() {    std::println("{}", std::stacktrace::current());}
Text 
0#  main at /app/example.cpp:5 [0x5ee42e3db747]1#  <unknown> [0x76e76dc29d8f]2#  __libc_start_main [0x76e76dc29e3f]3#  _start [0x5ee42e3db644]

string 和 string view 的 contains 函数

一个简单的查询函数，用来查询一个字串是否包含在字符串（string）或者字符串视图（string view）中：

C++ 
std::string{"foobarbaz"}.contains("bar"); // == truestd::string{"foobarbaz"}.contains("bat"); // == false

译者的理解：字符串终于也有 contains 了，不用再写 if (str.find("aaa") != std::string::npos) 了🤡

std::to_underlying

支持将枚举类型转为其底层类型：

C++ 
enum class MyEnum : int { A = 1, B, C };std::to_underlying(MyEnum::A); // == 1std::to_underlying(MyEnum::C); // == 3

spanstream

一种使用字符数组作为外部缓冲区的 strstream 的替代方案。该缓冲区不涉及所有权转移或重新分配。

C++ 
char input[] = "10 20 30";std::ispanstream is{std::span<char>{input}};int i;is >> i; // i == 10is >> i; // i == 20is >> i; // i == 30
C++ 
char output[30]{}; // zero-initialize arraystd::ospanstream os{std::span<char>{output}};os << 10 << 20 << 30;std::span<char> sp = os.span();

输入/输出指针

std::out_ptr 和 std::inout_ptr 是一种抽象机制，通过创建一个临时的“指针到指针”变量，在销毁时更新智能指针，以同时支持 C 语言接口和智能指针。

该机制还能在抛出异常时安全地管理相关内存的生命周期。

C++ 
// p_handle 写int c_api_create_handle(MyHandle** p_handle);// p_handle 同时读写int c_api_recreate_handle(MyHandle** p_handle);void c_api_delete_handle(MyHandle* handle);struct resource_deleter {	void operator()(MyHandle* handle) {		c_api_delete_handle(handle);	}};std::unique_ptr<MyHandle, resource_deleter> resource(nullptr);int err = c_api_create_handle(std::out_ptr(resource));// `resource` 现在在 `c_api_create_handle` 中独占内存所有权std::shared_ptr<MyHandle> resource(nullptr);int err = c_api_recreate_handle(std::inout_ptr(resource), resource_deleter{});// `resource` 现在在 `c_api_recreate_handle` 中共享内存所有权

std::optional 的 monad 操作

支持对 std::optional 的各种操作：and_then、transform、or_else。

C++ 
std::optional<int> parse_int(const std::string&);std::optional<int> ensure_non_negative(int);std::optional<double> default_value_or_empty(double);std::optional<double> stringToSqrtDouble(const std::string& input) {  return parse_int(input)    .and_then(ensure_non_negative)    .transform([](int x) {      return std::sqrt(x);    })    .or_else(default_value_or_empty);}

std::expected

std::expected 能在同一个类型中表达一个预期值和一个潜在的错误值。它还支持对预期值和非预期值（即错误值）进行多种 monad 操作。

使用 std::unexpected 来存储非预期值（即错误值）。

C++ 
enum class StringToSqrtDoubleError {    ParseError, NegativeNumber};std::expected<int, StringToSqrtDoubleError> parse_int(const std::string&);std::expected<double, StringToSqrtDoubleError> stringToSqrtDouble(const std::string& input) {    auto parsed = parse_int(input);    if (!parsed) return parsed;    auto parsedInt = *parsed;    if (parsedInt < 0) return std::unexpected(StringToSqrtDoubleError::NegativeNumber);    return std::sqrt(parsedInt);}

译者的理解：这个 std::expected 超级好用，之前有这种返回+错误的需求，不然就是在参数里开一个引用参数，来传递错误（丑），不然就得用异常把错误抛出来。现在用这个处理错误可以说是非常爽了。

std::unreachable

提供一种方法可以显式把代码路径标记为不可达。如果该代码路径被执行，则会导致未定义行为。

C++ 
enum class MyEnum { A, B, C };int convertMyEnumToInt(MyEnum e) {    switch (e) {        case MyEnum::A: return 0;        case MyEnum::B: return 1;        case MyEnum::C: return 2;        default: std::unreachable();    }}
